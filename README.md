# 传感器校准偏差复核

Bootstrap 区间估计的真实业务分析小型项目。完整模拟客户、痛点、上下游、算法公式与一天工作剧本见 [BUSINESS.md](BUSINESS.md)。

## 模块与业务流程
数据接入（JSON/CSV、字段验证、批次指纹）→ 参数化分析（异步 Python worker）→ 结果复核（指标、图形、明细、解释、批准）→ 定时分发（本地收件箱、CSV/JSON、SHA256）；另有业务总览和审计轨迹。
三个贯穿全栈的实体：Dataset 数据批次、Job 分析任务、Report 分发计划；辅助 User、Audit、Delivery。

## 快速启动
```bash
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```
访问 http://localhost:18206；后端文档 http://localhost:19206/docs；数据库宿主端口 17706。
`SEED_DEMO=true` 自动幂等 seed；不覆盖用户修改。手动 seed 命令可重复执行。

## 技术与本地开发
Python 3.12 / FastAPI / SQLAlchemy / NumPy / SciPy / scikit-learn；PostgreSQL 16；Redis 7；Nginx；原生 HTML CSS JavaScript ES modules（用户指定）。后端所有校验、持久化和算法在服务端。无前端打包步骤。
后端：安装 backend/requirements.txt，设置 DATABASE_URL、REDIS_URL、JWT_SECRET、ARTIFACT_DIR 后在 backend/ 执行 `python -m migrations.initial`、`python -m scripts.seed_demo`、`uvicorn src.main:app`，另开 `python -m src.worker`。前端使用带 /api 反向代理的 Nginx，直接打开 index.html 不支持 API。

## 环境变量与 Docker
COMPOSE_PROJECT_NAME=sensor-bootstrap；FRONTEND_PORT=18206；BACKEND_PORT=19206；DB_PORT=17706；DB_PASSWORD、JWT_SECRET 见 .env.example；SEED_DEMO 默认 true。共享命名产物卷供后端下载与 worker 写入，数据库/Redis 各持久卷。
恰好五服务均有健康检查。Redis 队列加 SQL 排队状态兜底；worker 按 next_run 生成本地收件箱文件。周期 60 秒至 30 天。分发结果为批准分析的固定快照；若需新数据重新计算并建立新计划。当前不连接邮件或企业聊天。
错误响应、请求编号、Redis 每 IP 每分钟 240 次限流、JWT 和数据库操作审计。演示密钥与密码仅供本机模拟；生产部署前配置独立密钥与账号。

## 批次交接包
`批次交接` 页面（`#/handover`）按数据批次导出 ZIP：样本记录、该批次全部已完成分析（含参数与结果快照）、这些分析创建的简报计划，以及对应归档原件；`manifest.json` 记录每个实体的原始编号与每份文件的 SHA256。

- 导出：归档文件缺失或校验不符时整包拒绝，不生成半成品包；包内 `files/` 保存归档原始字节。
- 导入：先整包校验（格式版本、引用完整性、样本字段、文件大小与 SHA256），任一失败即整包拒绝，不写入任何记录。校验通过后先原子写入归档文件，再用单事务落库整组数据。
- 接收方保留现有业务数据；目标编号冲突时重新分配新记录并保留 `origin_id` 映射（交接记录详情可查），不改写已有记录。
- 迁入的简报计划一律 `enabled=false`，需接收方负责人确认后手动启用；迁入归档文件名重新分配，下载内容与原件逐字节一致。
- 幂等与并发：以 `package_id` 为键，重复导入返回同一条交接记录；同一包并发导入由行锁串行化，只落一组。
- 中断恢复：`validating/importing` 状态下进程中断，未提交事务自动回滚；启动扫描把遗留记录标为 `recovering`，重新导入同一包沿用暂存文件继续，不产生重复。导入未完成的整组样本、分析、计划与归档在业务页面和总览统计中均不可见。
